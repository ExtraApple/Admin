## 1. 审计基线与隔离环境

- [ ] 1.1 固定当前代码基线、Go／服务构建信息、当前 `file-management`、`internal-messaging`、`logging` 规格和 messaging runbook 版本；记录去敏配置形状。
- [ ] 1.2 创建独立 MySQL schema、Redis namespace、MinIO bucket／对象前缀和临时服务配置；确认不会连接共享开发库或生产数据。
- [ ] 1.3 启动当前真实 App 组合根并验证真实 HTTP、JWT、MySQL、Redis、MinIO 链路；记录启动和资源清理入口。
- [ ] 1.4 创建固定夹具：超级管理员、受限管理员、发送者、当前受众、失去受众资格用户、组织外用户、删除私信关系后的原收件人、普通文件、消息图片、私信、群发和公告。
- [ ] 1.5 准备去敏 Runner、数据库 barrier、对象存储故障状态和可清理的临时数据；明确真实基础设施故障与测试专用故障注入的证据标记。

## 2. 消息可见性与撤销边界

- [ ] 2.1 通过真实消息入口创建私信、群发和公告，验证当前发送者／收件人／受众可以按现行权限读取列表和详情。
- [ ] 2.2 为各类消息绑定消息图片，通过真实图片读取入口验证可见用户能读取图片，且普通文件入口不能读取消息图片。
- [ ] 2.3 执行私信关系删除、消息撤销、公告过期和动态受众移除，分别验证列表、详情和图片读取均拒绝，并确认响应不泄露正文、图片或存储状态。
- [ ] 2.4 使用组织外用户、无受众资格用户和受限管理员重复访问代表性消息与图片入口，记录 HTTP 状态、稳定错误码、响应数据和数据库投影。
- [ ] 2.5 固定撤销／过期／受众变化与详情或图片读取的确定性交错，确认已提交的可见性事实优先于陈旧读取上下文。

## 3. 文件、对象与元数据一致性

- [ ] 3.1 注入普通文件对象上传成功但 File Record 写入失败，验证补偿删除、错误响应、数据库记录和对象最终状态。
- [ ] 3.2 注入普通文件删除、轮转对象移动或轮转元数据更新失败，验证数据库记录、对象副本和后续可恢复定位。
- [ ] 3.3 让消息图片清理登记事务失败、对象删除失败、对象超时和对象不存在，验证 File Record、清理队列、冻结位置、重试计数和稳定错误码。
- [ ] 3.4 验证消息图片绑定与清理登记、轮转与清理之间的正反提交顺序，确认已绑定图片不登记清理、已登记图片不再绑定或读取，且不误删对象。
- [ ] 3.5 使用多个 Worker 竞争同一重试，验证只有一个条件预留赢家；验证第 24 次终态、`dead` 不重入和第 24 次预留崩溃边界。
- [ ] 3.6 在对象已删除后注入数据库终结失败及迟到失败结果，验证队列可恢复、不会重建已完成状态、不会复活 File Record 或覆盖较新结果。
- [ ] 3.7 对缺桶、权限拒绝、超时、NoSuchKey 和跨桶路径分别验证错误分类、受信位置限制、对象副本状态和可重试性。

## 4. 审计日志与查询范围

- [ ] 4.1 触发文件上传／绑定／读取拒绝／清理失败、消息发布／撤销／过期及资源相关 Outbox／Consumer／DLQ 路径，记录 RuntimeLogger 输入和最终 sink 输出。
- [ ] 4.2 验证最终日志只包含稳定操作、操作者／目标／组织 ID、结果、稳定错误码、任务／队列 ID、重试次数、时间和计数等允许字段。
- [ ] 4.3 验证正文、HTML、图片、bucket、object key、签名 URL、Token、密码、凭据、邮箱／手机号和原始基础设施错误不会出现在日志或审计 metadata。
- [ ] 4.4 通过真实审计查询入口验证权限、操作者数据范围、组织范围、分页和 total；对 HTTP 与后台记录分别核对可见范围和字段口径。
