## Context

Identity GORM seed.go:73-82两处Count仅返回bool。真实单条1317后count=0而原tx.Error=nil，随后restoreSeedAdminUser写密码并提交；正常重启对照保留原密码。Finalize由App现有事务拥有，错误链已经能阻止Build/Run。

依据[proposal](proposal.md)及其引用审计/裁决；本文件描述未来实施，不代表已改代码或执行验收。实际路径遵ADR0006的internal业务模块、caller-owned Contract与App唯一组合根，不沿用已登记为旧提示的顶层技术目录。

## Goals / Non-Goals

**Goals:**

- 让active-admin与用户角色绑定两处Count明确返回查询错误，禁止用false代替读取失败。
- 错误沿现有Finalize／App启动链返回，失败阶段不提交且不进入HTTP服务；已成功阶段仍保留。
- 正常识别已有管理员时不重置密码；普通用户名不误提升；Seed仍不创建或修复授权版本。
- 补充单条语句故障、正常重启与原程序启动拒绝的针对性回归。

**Non-Goals:**

不新增整轮Seed事务、自动重试、授权版本修复、管理员密码运维重置接口或旧Token可用性结论。

## Decisions

### 1. 读取结果与错误分开

两处存在性helper返回(bool,error)，直接消费Count返回对象的Error；仅成功查询后的零计数表示不存在。SeedAdminUser逐次检查错误再做分支。

**理由与替代方案**：比读取原tx.Error可靠：已观察链式查询错误不会自动污染原tx；不增加布尔错误标志或字符串匹配。

### 2. 沿现有阶段错误链失败

保留Foundation、同步、Finalize各自提交边界；本次Finalize出错直接返回App并阻止HTTP Run。日志保留安全因果，不记录密码/Hash/DSN。

**理由与替代方案**：不做全轮Seed事务、不吞错假幂等、不重试1317，也不新增恢复配置。

### 3. 清洁迁移调用与不写版本

更新所有helper调用及适用测试；未获得“确实不存在”不能创建/恢复；第二个Count错误保留真实原因，不伪装普通用户名冲突。

**理由与替代方案**：两个helper是同根因修复，但只有active-admin错误后的密码覆盖已有真实反例；不重复计算缺陷。

## Risks / Trade-offs

- 查询故障被包装为业务不存在 → 同时覆盖active-admin和角色绑定故障，检查错误cause及未写密码。
- 启动失败前已有阶段已提交 → 证据明确阶段边界，只要求失败阶段回滚及复跑幂等，不谎称全库未变。

## Verification

- 复用定向报告的正常重启与单条Count故障前提；仅中断目标SQL，后续读取仍健康，密码Hash/身份/绑定/版本不变。
- 角色绑定Count单独失败，返回原错误且不得恢复或创建用户。
- 原main启动在故障时返回失败且不监听HTTP；撤故障后同配置可幂等启动，已有管理员仍用原密码。
- 无管理员正常初始化、配置普通同名用户拒绝、Seed不创建/修复版本均保留；不使用已过期JWT推断旧会话状态。

只为真实消费者行为/边界保留适用回归；HTTP权限、跨模块事务和并发需要真实存储/原程序场景，Fake或SQLite仅保留自身局部效力。当前只创建工件，未执行这些检查。
