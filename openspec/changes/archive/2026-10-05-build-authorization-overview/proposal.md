## Why

当前正式工作台登录后会直接跳转到第一个可见管理模块，超级管理员缺少一个统一核对授权配置、数据范围和影响摘要的入口。角色页面已有局部配置风险提示，但风险规则、影响范围和首页导航没有统一读取模型，管理员需要跨角色、用户和组织页面手工拼接事实。

本 change 首先服务超级管理员的授权核对任务，同时保留按操作者数据范围裁剪的语义，避免把“超级管理员优先”实现成固定返回全局数据的特殊接口。

## What Changes

- 新增只读授权总览读取能力，统一返回当前操作者范围、角色／用户／组织摘要和配置风险。
- 新增分页授权风险清单，承接总览前 N 条之外的完整风险核对。
- 将配置风险按目标对象聚合，并按潜在影响范围排序；风险项只读并跳转到角色、用户或组织详情。
- 将超级管理员登录后的工作台首页改为授权总览，而不是按导航顺序跳转到角色管理。
- 新增范围带，表达当前操作者真实数据范围；不提供会改变授权事实的临时范围切换。
- 新增授权总览的桌面／移动端响应式布局、可访问状态、加载态、空态和错误态。
- **非目标**：不做精确的每用户最终有效权限分析、在线会话统计、授权历史时间线、审批队列、风险批量修复或组织创建功能。

## Capabilities

### New Capabilities

- `authorization-overview`: 授权总览和分页授权风险清单的后端读取契约、数据范围、风险规则、排序和只读行为。

### Modified Capabilities

- `admin-workbench`: 超级管理员首页进入授权总览；新增范围带、风险跳转和总览响应式交互要求。

## Impact

- **后端路由**：新增 `GET /api/admin/authorization-overview` 和 `GET /api/admin/authorization-risks`，分别使用总览和风险清单权限码。
- **后端模块**：由 Authorization Application 读模型定义跨模块最小 Contract，装配角色、菜单、用户和组织读取能力；不新增一级 `internal/adminworkbench` 模块。
- **前端**：更新工作台首页、导航、路由、API models 和管理样式；新增授权总览页与风险清单页。
- **契约**：沿用现有四字段 JSON 响应、稳定错误码、数据范围过滤和 Route Catalog/OpenAPI 规则。
- **数据与基础设施**：不新增表、Redis key、MinIO bucket 或持久化授权历史；读取结果来自现有角色、权限、菜单、用户和组织关系。
