## Context

工作台已有 215 个 Go 测试文件和 14 个 Web 测试文件，覆盖后端契约、应用层状态和组件行为；尚无一个跨真实浏览器、真实 HTTP、真实角色权限和真实依赖的联合验收矩阵。当前 `8080` 被 `steamwebhelper` 占用，前端未运行，不能直接假设现成环境。

前端有 9 个可见区域、约 59 个引用 API 路径；后端约 94 个 Route Descriptor。消息模块有 HTTP 与 WebSocket API，但没有前端页面。Chrome DevTools MCP 能观察网络、控制台、DOM/a11y、截图、Lighthouse 和性能 trace，也能模拟离线／慢网、视口和主题，但不是完整测试框架。

## Goals / Non-Goals

**Goals:**

- 建立可执行的页面×接口×权限×期望矩阵，而不是无差别全笛卡尔积。
- 用真实浏览器验证登录、导航、读取、代表写链路、权限错位、会话恢复和资源加载。
- 用 curl／SQL／Redis／日志补齐精确契约和状态断言。
- 覆盖离线／慢网、核心错误、依赖故障、WebSocket 和代表页面可访问性／性能。
- 生成脱敏、可复核的 evidence，并保持不修改业务代码。

**Non-Goals:**

- 不修改业务代码、路由、schema、权限码、菜单或前端页面。
- 不新增 Playwright 或永久 E2E 框架。
- 不把 94 个 Route Descriptor 全部做浏览器深测。
- 不做全量 MySQL／Redis／MinIO／RabbitMQ 混沌测试。
- 不连接生产环境，不重复消息前端页面（当前无 UI）。

## Decisions

### 1. 使用全新隔离栈

| 组件 | 端口 | 说明 |
|---|---|---|
| MySQL 8.0 | `13306` | 独立库 `admin_workbench_acceptance` |
| Redis 7 | `16379` | 会话、验证码、WebSocket ticket／刷新 |
| MinIO | `19000/19001` | 头像、文件、对象存储 |
| Mailpit | `11025/18025` | 邮箱验证 smoke |
| RabbitMQ | `15672/15673` | 管理 UI `15672`，AMQP `15673` |
| 后端 | `18080` | 临时配置、真实 SMTP Mailpit、RabbitMQ |
| Vite | `15173` | `ADMIN_API_TARGET=http://127.0.0.1:18080` |

后端从临时目录运行构建产物，读取临时 `config.yaml` 与 `.env`。`browser_session.origin` 为 `http://localhost:15173`。仓库默认配置和 `.env` 不修改。`8080` 的 Steam 占用不再使用。

### 2. 分层矩阵，不做全笛卡尔积

`matrix.md` 把验收拆成页面、API、角色、失败、WebSocket、可访问性／性能六层：

- 页面层：全部可见路由加载＋读取＋权限渲染＋空／错误状态。
- 写链路：每个模块一条代表链路，高影响操作全部覆盖。
- API 层：59 个前端引用路径成功契约；94 个 Route Descriptor 静态元数据；代表性错误契约。
- 角色层：四类用户×页面／API 代表矩阵。
- 失败层：离线／慢网、401／Refresh、403、422、409、后端断连、Redis 故障。
- 非功能层：WebSocket、a11y、性能基线。

不用“所有页面×所有接口×所有角色×所有失败”的全组合；矩阵按风险和集成缝抽样。

### 3. 基础夹具＋关键 UI 写操作

- `admin`：全部权限、全局数据范围。
- `connectivity-manager`：用户／角色／组织读取，用户角色与组织有限写；数据范围限定组织 A；无菜单／API／审计管理。
- `connectivity-viewer`：无管理权限，只能登录和个人资料。
- `connectivity-disabled`：停用用户，验证登录拒绝和旧会话失效。
- 组织 A／B：各有一个目标用户；manager 只能管理 A。

基础角色、用户、组织、数据范围通过 Seed／API／SQL 准备；角色权限编辑、用户归属、组织移动、菜单／API 同步等关键写链路保留真实 UI 操作。验证码使用 Redis `captcha:<id>` 固定 fixture，不使用 OCR。

### 4. Chrome DevTools MCP＋curl／SQL／日志

- Chrome MCP：真实浏览器登录、导航、网络请求／响应、控制台、DOM/a11y、截图、离线／慢网、Lighthouse、trace。
- curl：状态码、错误码、统一信封、权限边界和原生响应。
- SQL／Redis：数据范围、授权版本、会话、ticket、限流和状态断言。
- 日志：关联请求、错误和审计事实。

MCP 不是测试框架；所有“页面看起来正常”的结论必须有网络、控制台或状态证据。不引入 Playwright。

### 5. 失败注入顺序

先完成读取和正常写链路，再执行可恢复失败：

1. 离线首屏／保存、慢网登录／保存、重复提交。
2. Access 过期／Refresh 失败、退出、停用用户旧会话。
3. 403、422、409、404／405。
4. 后端断连与恢复。
5. Redis 停止与恢复。
6. WebSocket 未授权、断线重连、消息刷新。
7. a11y／性能最后执行，避免故障状态污染基线。

预期失败（401／403／409／422／503）必须记录为矩阵预期，不算缺陷；未预期 5xx、契约解析失败、权限错位或“失败却显示成功”算不通过。

### 6. 通过标准

- 矩阵所有预期状态、UI 状态和 DB／Redis 状态通过。
- 无未解释控制台错误或未处理 Promise rejection。
- 无意外 5xx、统一信封解析失败或权限导航／API 错位。
- a11y critical／serious 为零。
- 性能基线已记录；首轮不设未经验证的数字阈值。
- 证据完整、脱敏、可复核，临时环境已清理。

### 7. 证据与失败处理

执行后写 `docs/reviews/evidence/workbench-connectivity-YYYY-MM-DD.md`，记录环境、矩阵结果、HTTP 状态／错误码、网络失败、控制台、DB／Redis 状态、截图、a11y／性能基线和清理结果。未执行项明确标记。

测试工具自身的命令／选择器问题最多自行修正 3 次；产品行为、权限语义、接口契约或范围决策出现问题时暂停并汇报，不通过放宽断言、跳过场景或修改业务代码使测试通过。

### 8. 清理

停止后端、Vite、浏览器页面和全部容器；删除临时卷、配置、截图临时文件和凭据文件；保留 evidence 与必要的脱敏日志片段。不删除仓库默认配置、业务代码或用户本地 `.env`。

## Risks / Trade-offs

- **端口冲突**：`8080` 被 Steam 占用；统一使用 18080／15173 等隔离端口。
- **矩阵膨胀**：用风险抽样和代表写链路控制；不追求全接口浏览器深测。
- **MCP 限制**：无原生请求 mock；用离线／慢网、服务停止、真实错误夹具和 `initScript` 兜底。
- **RabbitMQ 额外复杂度**：WebSocket 刷新依赖 RabbitMQ；启动失败则降级为 ticket／升级／重连，并标记消息刷新未执行。
- **测试数据污染**：独立库／卷；夹具唯一；失败场景后按顺序恢复依赖。
- **证据泄露**：截图不展示 token、Cookie、密码、授权码；证据只记录脱敏错误码和状态。
- **弱网误判**：Vite 资源也被限速；先加载页面再注入交互失败，首屏弱网单独记录。
