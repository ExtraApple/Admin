## Why

现有个人资料页只展示资料、邮箱状态和角色，尚未把已有昵称、头像和密码接口接成可用的自助维护流程。需要在已完成的会话恢复机制上补齐这些操作，同时修正会造成普通读取故障误登出及超长新密码返回内部错误的接入障碍。

## What Changes

- 保留现有 `/profile`、视觉、主题和账号菜单；资料、头像、密码分别提交，同一时间只展开一个编辑区。切换或离开时确认真实未保存修改，取消仅还原当前区，提交期间防止重复操作。
- 资料编辑仅开放昵称：非空、不能全为空白、最多 100 个 Unicode 字符，不自动 Trim 或改大小写，不提供清空。前端只发送昵称；用户 ID、用户名、邮箱、角色与启用状态保持只读，既有后端本人邮箱协议不删除。
- 头像支持本地选图与预览、显式保存、取消及确认后恢复默认；选图不会自动上传，不增加裁剪等图片编辑。沿用静态 JPEG／PNG／WebP 和服务端标准化规则，同步修正遗漏 WebP 的接口说明。
- 新增受认证的头像上传大小规则读取；前端不硬编码部署上限。规则缺失／读取失败只阻止选图和上传并提供重试，不拖住头像展示、恢复默认或其他编辑；明确认证失效仍执行全局会话处理。
- 昵称、头像写入成功后同步当前标签的个人页和顶栏，重新取受控头像而不是继续使用旧缓存或把本地预览当成保存结果。其他标签重新进入个人资料或刷新时读取最新显示，不新增跨标签资料广播；并发沿用最后实际写入成功的值，不引入资料版本或编辑锁。
- 改密表单遵守现有复杂度、新旧不同和确认一致规则。普通校验失败保留输入；取消、切换、实际离开或会话挂起／失效时清空密码，不持久化，不作为同会话恢复草稿保留。
- 改密明确成功后复用现有 Cookie 退出流程并引导重新登录；退出失败分别说明“密码已修改”和“服务端退出未确认”，保留重试退出或显式登录入口。未知写入结果不假报成功或回滚，不自动重发写请求或试登录；旧用户／会话的晚到结果不得改写或退出新身份。
- **BREAKING**：涉及的用户读取与共享回读只把已确认不存在映射为既有认证失效；真实数据库故障改为安全 `500 / IDENTITY_INTERNAL_ERROR`。保存已提交但回读失败不伪称回滚，并迁移受影响消费者和行为测试。
- **BREAKING**：新设密码统一受现有 bcrypt 的 72 个 UTF-8 字节上限约束，超限改为字段可定位的输入错误，不再进入 Hash 后报 500；注册等共享设密入口一并对齐，不截断、不更换算法，不收紧登录或旧密码验证。

### 非目标

- 不增加邮箱换绑／验证／重发、手机绑定、管理员代改本人资料或角色／状态编辑。
- 不重做登录页、工作台壳层或会话框架，不新增普通退出二次确认。
- 不增加裁剪、旋转、拍照、网络图片导入或前端独立图片安全校验器。
- 不引入自动重放、资料实时广播、CAS、编辑锁、全新资料版本、密码算法迁移或历史密码重置。
- 不增加上传配置管理、遥测、清理任务、数据库表／列、基础设施或依赖；既有其他头像清理／审计问题不顺带扩展。

## Capabilities

### New Capabilities

无。自助维护归属既有用户管理与工作台能力。

### Modified Capabilities

- `user-management`：新增头像上传规则读取，明确本人资料／改密及共享用户读取的故障分类，新设密码字节边界与注册调用者对齐；补清现有文件上限和 multipart 开销的区别，保留已有头像与邮箱行为。
- `admin-workbench`：新增个人资料页的三个独立编辑流程、局部规则失败、当前标签显示同步、改密退出结果区分与敏感密码草稿例外；扩展已有编辑保护，不削弱原有会话与业务页面保证。

## Impact

- **后端**：`internal/identity/{application,adapters/http,dto.go}` 及必要的调用者、错误映射与测试；保留已有 Repository 的不存在错误信号，不把 ORM 类型带进 Application。HTTP 描述与 OpenAPI 继续通过 Route Catalog Snapshot 投影，唯一装配仍在 `internal/app`。
- **路由与协议**：新增 `GET /api/user/avatar-upload-policy`，静态访问等级为 Authenticated；四字段信封 `data={max_bytes: 正整数}`，值源于当前 `file_upload.avatar_max_size_mb`。复用 `GET/PUT /api/user/info`、`POST/DELETE /api/user/avatar`、`PUT /api/user/password`、`GET /api/user/context` 和既有 Cookie Logout；不改这些 URL，不新增 Permission Code 或访问等级。
- **前端**：`web/src/pages/ProfilePage.tsx`、集中 `api.ts` 的 FormData 通路、用户／规则类型、会话上下文与当前用户头像的刷新接入、既有未保存保护；注册界面同步密码提示与校验。不新增第二套认证 Client、状态库或持久化用户资料。
- **模型与配置**：只增加只读规则 DTO／前端状态，不迁移用户或授权模型；不新增 Redis key／MinIO bucket／配置项，保留 `user_access_versions`、Cookie 与授权失效规则；头像 SHA-256、object key 和存储配置不得作为显示版本对外暴露。
- **交付边界**：本轮仅生成 change-local 规划工件，不修改业务代码、主规格、现有 TODO 或已归档证据。实施时更新真实文档与 TODO 状态，完成后端／前端回归及真实 HTTP／浏览器验收后同步两份主规格；提交、推送和归档另行执行。
