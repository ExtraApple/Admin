## Context

本change只规划前端主题能力，采用用户讨论中已选择的三态模式、默认跟随系统、浏览器级保存、全站覆盖、按钮菜单、保留亮色风格及跨标签立即同步。当前尚未实现或运行主题验收。

实际仓库是React 19／TypeScript／Vite／Tailwind前端与`internal/`业务模块组合，不沿用旧提示中的顶层技术目录。现状依据：

- `web/index.html`固定声明`color-scheme=light`，`main.tsx`直接挂载App；尚无主题启动或系统外观监听。
- `styles.css`已有语义变量和Tailwind映射，但按钮、输入框、卡片、弹窗等仍存在固定颜色；`management.css`另有`--mg-*`亮色变量、固定白底及状态色，Portal浮层不能只靠`.management`容器继承。
- `WorkbenchShell.tsx`已有右上角个人资料／退出区，`AuthPages.tsx`有共用AuthFrame；可各接入同一个选择组件，不改导航或复制模式逻辑。
- 现有`components/ui/dropdown-menu.tsx`已导出RadioGroup／RadioItem，支持三项单选及键盘交互，无须新增主题或组件依赖。
- `admin-workbench`已规定真实服务、冷白／深海青基线、Token只驻留内存和导航分组只在挂载周期保存。外观偏好是独立例外，不扩大其他数据的持久化范围。

## Goals / Non-Goals

**Goals:**

- 用户选择light／dark／system；只有system响应系统外观变化，未保存时默认system。
- 同浏览器、同源页面共享选择，重开后保留；系统变化和其他标签的选择立即反映到外观及菜单选中态。
- 在正式页面首次呈现前应用有效外观，保持Portal、原生控件及全部页面一致。
- 保留亮色风格、青绿色品牌及原布局／字体，通过语义色补齐协调暗色和各交互状态。
- 外观变化不重建业务页面、不丢输入／弹窗／焦点、不导航、不改变会话或产生业务请求。

**Non-Goals:**

账号级设置、跨设备同步、服务端存储、API／模型／Redis／MinIO／权限变更；布局／字体／导航重做；后台契约修复或全量审计；持久化Token、业务表单或导航分组；修改`preview.html`、生成新ADR、自动同步主规格或归档。

## Decisions

### 1. 区分所选模式与实际外观

模式为`light | dark | system`，实际外观仅为`light | dark`。system依据`prefers-color-scheme: dark`解析；不能把解析结果回写成固定模式。文档根节点分别表达模式和实际外观，CSS和原生`color-scheme`使用实际外观，菜单按模式勾选。

**理由与替代方案**：只保存当前颜色会丢失“跟随系统”的意图；三个页面各自维护布尔值会导致模式和Portal分裂。不做三态循环按钮。

### 2. 前置启动与运行时共用一个最小主题所有者

计划新增`web/public/theme.js`，在`index.html`的head中以同源普通脚本、非async／defer的方式于页面内容和应用挂载前加载。脚本只负责主题：读取偏好、解析系统外观、设置根节点状态／`color-scheme`，并提供选择、稳定快照及订阅能力。它是唯一主题状态和监听所有者，不依赖React或业务API。

计划在`web/src/lib/theme.ts`提供薄的TypeScript／React适配，使用现有React订阅能力消费这一所有者。初始化快照由启动模块提供，不在useEffect中重新计算后覆盖首屏，不按主题给App或路由设置key。订阅可移除、快照稳定，React StrictMode不重复建立全局监听。不得保留互不关联的“启动版”和“React版”主题算法。

**理由与替代方案**：挂载后才初始化会在保存暗色或系统暗色时先画亮色；在HTML复制一份与运行时各自演进的解析代码容易漂移。同源静态脚本复用Vite已有public资产交付，避免新增库、构建插件或放宽安全策略；代价是一个需要先到达的极小静态资源，必须验证部署产物中真实可用而非被SPA fallback返回HTML。

### 3. 浏览器保存和跨标签事件保持单向

使用同源localStorage专用键`admin-workbench.theme`，仅保存三态枚举，不存账号标识或实际颜色。选择在当前页面立即应用并持久化；其他标签监听该键的storage事件，重新解析并应用，但不把收到的事件再次写回形成循环。保持system的已打开标签各自响应系统外观变化；固定模式忽略系统外观变化。移除该键或清空对应存储视为无已保存选择，回到system。

读取失败或保存值不是合法枚举时，按无有效偏好处理；写入不可用时本页仍可应用选择，不伪称已跨重开保存，也不通过账号、Cookie或服务端做替代持久化。系统媒体查询不可用时采用亮色作为安全显示基线，不中断登录或业务页面。这些是局部浏览器边界的保守工程处理，不引入新的账号设置或后端修复策略。

**理由与替代方案**：浏览器级归属无需新增身份绑定和迁移；localStorage事件可覆盖同源其他标签，不需要BroadcastChannel、轮询或全局设置框架。退出只清理现有会话，不清理主题键。

### 4. 复用一个可访问的选择组件

计划新增共用ThemeSelector，使用现有DropdownMenu／RadioGroup／RadioItem及Lucide图标。工作台放在既有top-actions，公开认证页面放在AuthFrame可达位置；窄屏仍可操作。按钮有明确外观名称和当前模式，菜单显示“亮色”“暗色”“跟随系统”及唯一选中态；可以补充当前实际外观，但不得用它替换system的选中标记。

支持键盘打开、选择和关闭，并按现有Radix约定恢复选择入口焦点。业务焦点保持约束主要针对系统／其他标签被动更新；主动操作主题菜单允许正常的菜单焦点流转，但不能跳到其他业务字段。

**理由与替代方案**：按钮菜单符合已选择的交互并节省现有工具栏空间；三段常驻或循环按钮均不采用。入口不依赖登录和管理权限。

### 5. 在根层提供语义颜色，管理变量只做别名

根层分别提供亮／暗的背景、表面、文本、次级文本、边框、输入、强调、成功／警告／错误、焦点与遮罩等语义角色；现有Tailwind映射和通用组件继续使用这些角色。`--mg-*`改为对根语义色的引用，不保留第二套独立主题。清理本次覆盖组件中固定白底、固定状态色和hover色；通过document/body Portal挂载的菜单、Dialog、Sheet、Tooltip及其遮罩都能取得根主题。

亮色沿现有冷白／深海青风格，暗色使用协调的深色表面和青绿强调，不做整体反色。允许为可读性微调颜色，但不修改字体、排版、功能入口或将状态仅用颜色区分。普通正文对比度至少4.5:1，大字及关键非文本边界至少3:1；焦点、选中、禁用、错误、表格悬浮和原生表单都逐一核对。

**理由与替代方案**：仅给body加深色会留下白色卡片和Portal；每页再维护一份dark覆盖会继续产生两套约定。固定为语义色可让后续页面复用，并保持本次边界只涉及外观。

### 6. 验收以消费者结果和真实页面为准

少量永久回归仅覆盖有实际出错风险的状态边界：保存模式与系统解析优先级、恢复system、跨标签模式变化、无效／不可用存储。不检查源码同文、组件转发或mock调用次数。

实现阶段运行现有前端typecheck／test／build门禁；浏览器必须实际打开正式入口，观察首次加载、刷新／重开、系统切换、固定模式、双标签、公开页、已登录管理页以及Portal。业务状态证明须在真实角色或用户编辑中保留未保存输入及业务弹窗，让另一标签改变主题并核对路由／焦点／会话及业务请求未变化，不能用静态样稿或假登录代替。

生成构建产物时使用独占临时输出目录，保留用户现有`web/dist/`和`live-login.png`；真实后端验证使用独占测试身份／数据和可清理环境，不对共享业务库进行验收写入。保存必要去敏截图／网络观察和结果记录；规划工件或构建通过都不等于页面已验收。

### 7. 发布基线与工件边界

没有其他活跃change作为功能前置；前置是当前已同步的`admin-workbench`主规格。delta完整保留“正式工作台使用真实服务与已审核的界面基线”两个原场景，只扩展视觉说明，再新增主题要求；不得覆盖认证、授权、分组状态或编辑离开确认等其他Requirement。实现验收后才按独立流程同步／归档，本次所有实施任务保持未完成。

## Risks / Trade-offs

- 启动资产缺失或顺序错误导致闪白 → 实际构建检查`/theme.js`作为JS可获取，并用保存暗色／系统暗色下的首次导航观察验证，不只看最终DOM。
- 局部管理变量／Portal仍固定亮色 → 根层语义色和管理别名统一；两个外观逐页面、组件和浮层检查。
- 被动外观变化重挂载页面、丢输入或焦点 → 只更新外观快照，不改路由／session key，用双标签真实编辑观察证明。
- 模式与解析外观混淆、storage回写循环 → 分离状态、单一所有者、事件接收不写回，并检验从system到固定再返回system的行为。
- 浏览器禁止存储 → 本页切换仍可用但持久化受限；不扩大为账号／服务端fallback，保存失败不阻断业务。
- 主题选择被扩成UI重做或业务审计 → proposal非目标和独立任务约束；发现具体业务违约另行留证并讨论，不在本change顺带改规则。

## Migration Plan

无数据库迁移、存量数据回填、后端部署协议或既有浏览器键迁移。前端部署需同时交付入口、主题静态脚本、应用脚本与样式，沿现有静态资源路径使用；不修改API权限目录或后端路由注册。回滚使用上一完整前端构建，浏览器中的主题枚举键可保留且不会成为认证数据，不清理用户会话或撤销后端版本。

## Open Questions

已裁定的产品范围内无阻塞选择。具体暗色色值由实施时按现有品牌及双主题对比度／真实页面验证确定，不由此增加视觉重设计。此文是实现计划，不表示已交付主题脚本、页面适配或浏览器验收，也不创建ADR。
