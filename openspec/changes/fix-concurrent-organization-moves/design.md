## Context

UpdateUnit在事务外读取组织、父级及后代，再独立更新；C4受控等待证明两个请求各自通过校验后能共同成环。Repository已有纯ID/ParentID事实和Context事务，无现成拓扑写入锁。

依据[proposal](proposal.md)及其引用审计/裁决；本文件描述未来实施，不代表已改代码或执行验收。实际路径遵ADR0006的internal业务模块、caller-owned Contract与App唯一组合根，不沿用已登记为旧提示的顶层技术目录。

## Goals / Non-Goals

**Goals:**

- 将拓扑读取、范围/父级校验与父级写入置于同一最外层事务与数据库串行化协议内。
- 使用Organization拥有的当前父关系锁定读取重新校验，不能沿用锁前RR快照或仅依赖进程mutex。
- 创建、移动、删除参与同一拓扑协议，保留根节点0及既有管理边界。

**Non-Goals:**

不在此实现I4组织层级依赖失效、不新增组织乐观锁API字段、全局分布式锁服务或自动重试策略。

## Decisions

### 1. Organization拥有锁定当前父图

新增本模块Repository能力（拟名LockOrganizationParents）在当前事务按id升序锁定读取现存组织父关系；用返回图进行祖先追踪，重新验证父级存在、自指/后代与管理前提后写入。

**理由与替代方案**：替代进程mutex、只锁两个目标或事务外后代快照；跨实例须消费同一数据库锁。锁定读取是current read，不能拿到锁后仍复用锁前RR快照。

### 2. 三类拓扑写入同协议

CreateUnit、真正parent_id更新和DeleteUnit在相同最外层事务先进入该协议，删除子级检查也基于锁定图。根0是合法哨兵；空图初始化与唯一编码交给同一事务/已有索引保护。

**理由与替代方案**：只让Update参与会被并发创建/删除绕过。无需新锁表、命名锁连接管理或应用外服务。

### 3. 复用一次必要父图计算

按锁定父图沿拟父级链判断是否回到当前节点，不重复构建整个后代列表；同一事务复用该图，父级写入后才做受控回读。

**理由与替代方案**：接受拓扑写入串行化和O(n)当前父图读取换确定正确性，不把生产规模/频率当已测事实；不增加可配置的第二种锁协议。

### 实施与规格发布依赖

- 功能/写入协议前置：无其他change功能前置。
- 共享Requirement发布基线：无更早change修改同名Requirement。
- 本delta对重复Requirement使用包含前置增量的完整正文，不能乱序归档覆盖。功能依赖与发布依赖不是同一含义；无功能依赖的源码工作可独立，但发布须按此基线。每个前置必须先实施、验证并按流程同步到主规格；若主规格另有变化，合并保留其新增场景，不以旧全文覆盖。

## Risks / Trade-offs

- 全父图锁增加写竞争 → 固定排序、保持事务短，不在锁内做HTTP/缓存；复用已有Runner有限锁失败处理，不新增重试承诺。
- 旧实例绕过协议或RR旧快照 → 停写全量切换；证明等待后current read与三节点交错，不只跑两个ID特例。

## Verification

- 复用C4受控真实UPDATE等待，两个根交叉移动不能都提交成环；拒绝方无自身残留。
- 三节点环、深层跨分支、创建/删除与移动并发、合法移动到根均覆盖确定暂停点与最终全图无环。
- 故障导致事务回滚后原父图不变；成功/拒绝仍保持原权限与manageable=false祖先规则。

只为真实消费者行为/边界保留适用回归；HTTP权限、跨模块事务和并发需要真实存储/原程序场景，Fake或SQLite仅保留自身局部效力。当前只创建工件，未执行这些检查。

## Migration Plan

无DDL/数据回填。涉及拓扑写入协议时先停止组织结构写流量并切换全部写实例，禁止新旧协议混跑；恢复写入前做受控原程序验收。回滚同样停写并全实例切换，保留当前数据，不自动修复历史环；已知旧版会重新暴露C4风险。

实施前确认上述依赖及既有DDL/装配，不打印凭据。此变更不新增HTTP路径、Redis key、MinIO bucket或权限码；涉及的现有入口和表见proposal。实施后更新对应审计状态与去敏证据，不能把剩余C6风险一并标完成。
