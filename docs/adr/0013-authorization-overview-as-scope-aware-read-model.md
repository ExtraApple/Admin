# 授权总览采用范围感知的聚合读取模型

Status: accepted

管理工作台下一阶段以超级管理员核对授权配置与影响范围为首要任务，首页定义为“授权总览”，而不是通用统计仪表盘。授权总览首版只展示按操作者数据范围计算的实时配置态势、授权影响范围摘要和可证明的授权配置风险；不承诺每个用户的最终有效权限，不引入授权审计时间线或审批队列，也不统计在线会话或历史失效数量。后端通过聚合只读接口和配套的分页风险清单接口统一计算这些事实，前端负责范围带、风险表达和跳转，不通过并行调用多个领域接口自行重算授权规则。

## Considered Options

- 前端组合角色、用户、菜单和组织接口：实现较快，但会产生不一致快照并把授权规则复制到前端。
- 仅保留角色管理作为默认首页：改动较小，但不能服务“核对影响范围”的首要任务。
- 引入精确用户级影响分析：语义更强，但超出首版范围；首版采用角色、用户数量、组织边界和授权版本重新校验规则的摘要，不显示在线会话数量。

## Consequences

- 聚合读取接口必须遵守操作者的数据范围；超级管理员优先不等于接口固定返回全局数据。
- 首版配置风险以已分配停用菜单、菜单权限码缺失，以及两类已被使用的高影响空配置为主：已绑定用户但无权限的启用角色、处于可管理范围但无角色的用户；普通新建对象和空组织不自动报警。执行后续授权修改时，详情页说明相关用户旧会话将在后续请求重新校验。
- 视觉设计可围绕只读“范围带”表达操作者的授权边界；风险项只提供原因、对象和授权影响范围摘要，并跳转到角色、用户或组织详情页，所有写入仍在领域详情页完成。
- 风险列表默认按授权影响范围排序，而不是按风险颜色或类型制造告警优先级；影响范围未知时使用稳定的类型与对象排序。
- 风险项按目标对象聚合：一个角色、用户或组织作为一条总览记录，携带问题数量和有限的类型摘要；具体问题在领域详情页展开。
- 总览只返回按影响范围排序的前 N 个风险对象；其余风险必须通过专用只读风险清单页继续核对，不能只返回不可操作的 `has_more` 标记。
- 聚合读取逻辑归属 Authorization Application 的读模型；它定义最小跨模块 Contract，App 只负责装配，HTTP 适配器只负责路由和响应协议，不新增 `internal/adminworkbench` 一级模块。
