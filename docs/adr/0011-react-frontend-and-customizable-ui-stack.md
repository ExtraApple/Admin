# 管理端采用 React 与可定制组件路线

## 状态

已接受；React 工作台、集中 Client 和角色／用户／组织页面已有代码实现。运行验收与发布结论以两个关联 change 的验收证据为准，本 ADR 不宣称浏览器或联合验收已通过。

## 背景

Admin 将在根目录 `web/` 建立管理端，以用户、角色和组织授权管理为首期场景。当前 `web/preview.html` 是覆盖角色、用户、组织、登录／注册及关键状态的可点击静态样稿，只使用示例数据、不连接后端，不是正式前端应用。角色详情以权限、已分配菜单和数据范围的并列授权剖面为设计重点；成套后台模板或组件库的默认外观不应取代这套设计。

前端还须遵守 [`standardize-api-response-contract` 的前端及联合验收要求](../../openspec/changes/archive/2026-10-01-standardize-api-response-contract/tasks.md)：集中解析业务响应、按稳定错误码本地化、展示字段级错误和登录锁定状态，并为下载、头像与原始 OpenAPI 响应保留非信封路径。选型不改变这些契约或后端职责。

## 决策

- 正式管理端使用 **React + TypeScript + Vite**。
- 使用 **Tailwind CSS** 管理页面样式与语义化主题变量；按需引入 **shadcn/ui** 组件，明确选择 **Radix UI** 作为交互基元，而不是沿用 shadcn/ui 新项目默认的 Base UI。
- 保留已审核的冷白／深海青视觉基线，以 [`web/preview.html`](../../web/preview.html) 作为实现时的视觉参照。正式角色详情将权限、已分配菜单、数据范围作为并列授权剖面呈现，不沿用早期样稿中暗示先后关系的“授权路径”；替换组件的默认中性色主题。样稿中的假数据和切换逻辑不得作为正式应用实现。
- 角色从分页列表进入独立详情页，让权限、已分配菜单、数据范围的并列剖面有完整展示宽度；不沿用早期样稿的左侧示例角色选择列。详情默认只读；三个授权维度分别进入各自的独立编辑页并独立保存，适应较长的权限分组、菜单树和组织树，不提供暗示三项可原子提交的统一保存入口。页面导航、角色授权剖面和业务状态由应用实现；只为所需交互引入基础组件，不采用成套后台模板。数据访问与错误处理在集中 API Client 中实现，组件不自行解析业务响应。
- 角色详情中区分“已分配菜单”与“当前角色缺少该菜单所需权限码”的配置风险；不提供角色级的“用户实际可见菜单数”。用户的最终菜单由其全部角色的菜单与权限共同决定，角色级风险提示不能代表某个用户的最终导航结果。
- 每个授权编辑页保存前展示本次授权变化摘要，并确认关联用户的旧会话将在后续请求失效；确认后仅提交该编辑页对应的配置。保存失败留在编辑页并保留未提交的选择，不将失败描述为已完成。
- 自定义数据范围编辑使用带层级的组织单位树和相互独立的复选框，持续展示已选择的单位；勾选上级仅选择该单位，不隐含所有下级。与之不同，“本组织及下级”的范围由后端按规则扩展。数据范围外仅用于展示层级的祖先节点不得作为可选授权目标。
- 用户列表快捷操作在按钮右侧以浮层展开，不撑高表格行或移动端卡片，也不遮挡下一位用户的操作按钮；点击其他位置、切换用户菜单或滚动时自动收起。

## 取舍

- **Vue 3 + shadcn-vue + Reka UI** 也能实现已审核的界面。选择 React 是组件生态与开发路线的取舍；在没有同口径构建和运行数据前，不把“Vue 一定比 React 沉重”写作决策依据。
- **Element Plus** 提供成套管理控件，但属于 Vue 生态，且其整体使用方式不符合本次选型偏好；shadcn/ui 更便于保持已审核的页面设计。
- **仅用 Radix UI 自建所有控件** 提供最大控制权，但会增加通用按钮、表单控件及交互样式的维护工作；shadcn/ui 提供可按需调整的组件源码。

该路线要求项目维护引入后的组件源码与主题变量；复杂表格、表单错误及响应状态仍须按业务契约自行组合和验证。现有实现采用 npm、React Router 和 Radix 组件，版本由 `web/package.json` 与 `web/package-lock.json` 固定；入口在 `web/src/App.tsx`，集中 Client 在 `web/src/lib/api.ts`。实现与联合验收门禁见 [`build-admin-workbench`](../../openspec/changes/archive/2026-10-01-build-admin-workbench/)；开发、部署及内存会话限制见 [README](../../README.md#管理工作台)。

## 后续约束：浏览器会话恢复

[ADR 0014：浏览器会话恢复](0014-browser-session-recovery.md) 替换初期“两种 Token 仅驻内存、整页刷新后重新登录”的会话限制，不改变本记录的 React／组件选型、集中 Client、视觉基线及编辑页面决策。Access 和用户上下文仍仅驻内存；Refresh 改由 HttpOnly 会话 Cookie 承载，不进入 WebStorage 或 JSON 响应。启动必须先续期并读取真实上下文，再显示受保护内容。

认证 Cookie 副作用通过跨标签 Web Lock 串行化，短状态锁保护无凭据的协调状态；持久退出意图阻止失败退出后自动恢复。有效 Access 期间的暂时续期失败保留编辑，到期后暂停而不卸载同一会话编辑；仅同 SID 且真实上下文复核通过才能恢复，换身份则清除旧编辑。必要 Cookie／存储／Web Locks 能力不可用时明确报告不可用，不回退到旧内存模式。具体失败语义与部署前提由 ADR 0014 规定；本补充不宣称联合或浏览器验收已经通过。
