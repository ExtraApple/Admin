# 使用三小时加速耐久性资格验收退出旧授权版本字段

## 状态

已接受。

## 背景

ADR 0004 规定观察期结束后才能停止 `users.token_version` 镜像写，并按固定顺序
移除运行时依赖和物理列。原 OpenSpec 使用一个完整发布周期和连续 7 个自然日作为
观察门槛，但当前项目不会持续运行这么长时间，授权版本指标又只存在于应用进程内，
无法从零散启动中恢复连续历史。

仅把数次短测试拼接成 7 日证据会产生虚假确定性；为本次类生产退出验收持续运行
7 日又超出用户愿意承担的时间成本。需要一个时间固定、负载有下限、可重复并能覆盖
进程重启与外部依赖的替代资格门槛。

## 决策

采用连续至少 3 小时的加速耐久性资格验收，替代原完整发布周期和连续 7 个自然日观察门槛。
资格验收必须：

1. 使用 Windows 本地隔离真实 MySQL 和 Docker Redis。
2. 连续运行至少 3 小时，完成至少 100,000 次混合认证授权操作，并维持至少
   8 个并发工作单元。
3. 覆盖登录、Access Token 校验、Refresh Token、Redis 黑名单以及会话失效后的
   Token 拒绝。
4. 完成至少 3 次受控应用进程重启，累计结果由进程外运行器持久化为机器可读证据。
5. 至少每 15 分钟、每次重启后和结束时执行新旧授权版本一致性扫描，全部差异为 0。
6. 非预期镜像写失败数、成功签发 Token 后缺行数和版本提升后缺行数均为 0。
7. 执行原子回滚故障注入，证明新表主写、旧字段镜像和用户生命周期更新不会部分
   提交。
8. 同时通过关键认证授权、真实 MySQL 并发事务和真实 Redis 组合门禁。

任务开始前的事件触发门禁仍然保留，用于防止在已知回归上继续推进；它不能替代
上述三小时资格验收。

## 取舍

- 三小时固定窗口显著降低等待成本，并通过工作量、并发、重启、扫描和故障注入提高
  单位时间内的缺陷暴露率。
- 该门槛不是对真实生产连续 7 日运行的统计等价替代，可能遗漏低频、长周期或真实
  流量分布问题。
- 进程外证据避免应用重启造成指标历史丢失，但增加一个专用资格运行器和证据格式的
  维护成本。
- 资格窗口内仍保留旧字段原子镜像；只有全部门槛通过并确认不再回滚到旧字段读取
  版本后，才能继续 ADR 0004 规定的退出顺序。
