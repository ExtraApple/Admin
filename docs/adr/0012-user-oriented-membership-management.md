# 用户管理以真实归属为准，并提供用户定向的归属修改

当前管理员用户列表只返回身份资料、单个旧 `role` 字段和状态，不返回用户的完整角色集或组织成员关系；角色和组织的现有分配接口则各自以角色、组织单位为中心，提交会替换该对象的全部成员。正式用户列表和详情要准确展示用户的多角色及组织归属，并允许从用户详情直接修改该用户的归属。因此，实施页面前须补齐相应的用户归属读取契约，以及由授权、组织各自负责的用户定向写入能力；不得用旧 `role` 字段冒充真实授权，也不得用前端读出全体成员、修改一人后调用全量替换接口。

角色归属与组织归属在用户详情分别编辑、分别保存；不暗示跨模块原子提交。组织详情的成员维护采用逐人增删，与用户详情复用用户定向的成员写入能力，不暴露现有整组覆盖操作作为单人成员编辑。组织树保留的数据范围外祖先仅供定位，正式读取契约须让前端区分这些节点与范围内可操作的单位。写入仍受现有受保护用户、授权版本和数据范围规则约束，界面应明确说明会话失效与操作失败的结果。具体接口形状、并发保护和授权边界应在实施时与后端契约一起确定；本决策未表示这些接口已经存在。

管理工作台在登录页提供公开注册入口，复用现有注册契约；注册得到普通用户身份，不自动获得管理权限，界面必须明确说明仍需管理员分配角色。用户管理页本轮不设计“管理员创建用户”；公开注册与管理授权是两个独立步骤。登录成功但无可用管理菜单时进入专用说明页，保留个人资料和退出入口，不虚构“审核中”状态，也不展示空白工作台。
