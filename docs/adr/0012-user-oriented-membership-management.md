# 用户管理以真实归属为准，并提供用户定向的归属修改

## 状态

已接受；真实用户归属读模型、用户定向角色／组织 PUT、版本冲突保护及对应工作台页面已有代码。实现存在不表示运行或联合验收完成；验收结论由 [`build-admin-workbench`](../../openspec/changes/build-admin-workbench/) 与 [`standardize-api-response-contract`](../../openspec/changes/standardize-api-response-contract/) 的证据共同决定。

## 背景与决策

原有管理员用户列表依赖单个旧 `role` 字段，角色和组织的原有分配接口各自以角色、组织单位为中心，提交替换该对象全部成员。正式用户列表和详情改为从实际关系读取多角色、可管理组织归属及隐藏归属标志；由授权、组织各自负责用户定向写入。不得用旧 `role` 字段冒充真实授权，也不得用前端读出全体成员、修改一人后调用全量替换接口。

角色归属与组织归属在用户详情分别编辑、分别保存；不暗示跨模块原子提交。组织详情的成员维护采用逐人增删，与用户详情复用用户定向 PUT，不暴露整组覆盖操作作为单人成员编辑。组织树通过 `manageable` 区分可操作单位与仅供定位的范围外祖先。两类 PUT 必须提交显式 ID 数组及 `expected_access_version`；成功返回新 `access_version`，过期返回 409 `AUTHZ_CONFLICT`／`ORG_CONFLICT` 并要求重新读取核对，不自动覆盖。写入仍受受保护用户、授权版本和数据范围约束；组织写入保留范围外关系及未移除关系的加入时间。接口集成边界见 [用户管理](../modules/user-management.md)。

管理工作台在登录页提供公开注册入口，复用现有注册契约；注册得到普通用户身份，不自动获得管理权限，界面必须明确说明仍需管理员分配角色。用户管理页本轮不设计“管理员创建用户”；公开注册与管理授权是两个独立步骤。登录成功但无可用管理菜单时进入专用说明页，保留个人资料和退出入口，不虚构“审核中”状态，也不展示空白工作台。
