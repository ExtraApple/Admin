# 文件管理实施文档

> **文档定位**：文件管理模块的已实现行为、接口迁移和 Apifox 验证说明。文件上传安全 V1 在 change 归档前以 `openspec/changes/harden-file-upload-security/specs/file-management/spec.md` 为准；同步后以 `openspec/specs/file-management/spec.md` 为长期权威规格。

## 当前状态

文件管理已完成管理员单文件上传、列表、详情、改名、删除、对象浏览、受控下载、图片预览、历史文件重新验证和文件轮转。

普通用户没有通用业务文件上传路由，只能通过专用头像接口上传头像。

## V1 数据流

```text
管理员提交单文件 multipart
  → 在解析表单前限制请求体
  → 校验文件大小、展示名称、扩展名、声明 MIME 和真实内容
  → 对图片、PDF、文本或 OOXML 执行专用校验
  → 服务端生成 UUID object key
  → 写入私有 MinIO bucket
  → 写入文件元数据和 validated 状态
  → 通过应用接口提供受控下载或图片预览
```

校验失败发生在对象存储写入之前。若对象写入成功但数据库记录创建失败，服务会立即尝试补偿删除新对象。

## 配置

文件上传安全参数属于非敏感部署配置，统一写入 `config.yaml`，不写入 `.env`：

```yaml
file_upload:
  max_size_mb: 50
  avatar_max_size_mb: 2
  download_url_expire_seconds: 300
```

| 配置项 | 合法范围 | 作用 |
|---|---:|---|
| `file_upload.max_size_mb` | 1～100 MiB | 管理员普通文件大小上限 |
| `file_upload.avatar_max_size_mb` | 1～10 MiB | 用户头像原文件和标准化输出大小上限 |
| `file_upload.download_url_expire_seconds` | 正整数 | 应用下载/预览签名 URL 有效期 |

非法配置会导致服务启动失败，不会静默使用更宽松的回退值。

HTTP 请求体还包含 multipart 边界和表单头，因此解析前的硬限制为：

- 管理员文件：`max_size_mb + 1 MiB`
- 用户头像：`avatar_max_size_mb + 256 KiB`

这部分开销只用于接收 multipart 元数据，不会提高实际文件大小上限。

## V1 允许的业务文件类型

`POST /api/admin/files` 只允许：

| 类型 | 扩展名 | 规范 MIME |
|---|---|---|
| JPEG | `.jpg`、`.jpeg` | `image/jpeg` |
| PNG | `.png` | `image/png` |
| WebP | `.webp` | `image/webp` |
| PDF | `.pdf` | `application/pdf` |
| DOCX | `.docx` | `application/vnd.openxmlformats-officedocument.wordprocessingml.document` |
| XLSX | `.xlsx` | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` |
| PPTX | `.pptx` | `application/vnd.openxmlformats-officedocument.presentationml.presentation` |
| TXT | `.txt` | `text/plain` |
| CSV | `.csv` | `text/csv` |

共同约束：

- 请求必须且只能包含一个名为 `file` 的文件 part。
- 空文件、额外文件 part、损坏 multipart 和超限请求均被拒绝。
- 扩展名、声明 MIME、检测 MIME 和专用验证结果必须归一到同一类型。
- `application/octet-stream` 不能作为上传白名单 MIME。
- TXT/CSV 只接受有效 UTF-8，可带 BOM，不接受 NUL、UTF-16、GBK 或 GB2312。
- DOCX/XLSX/PPTX 必须通过受资源上限保护的 Office Open XML 容器校验。
- 危险双扩展名、压缩包、旧版 Office、宏文档、HTML、SVG、脚本和可执行文件默认拒绝。

“`validated`”表示通过 `file-upload-v1` 格式策略，不表示已经经过病毒扫描。ClamAV 或其他外部恶意文件扫描属于 V2 后续能力。

## 数据模型与 API DTO

文件记录包含内部存储定位字段以及以下安全元数据：

```text
name
content_type
detected_content_type
size
uploader_id
validation_status
validation_policy_version
validation_error_code
validated_at
```

API 的 `FileInfo` 不返回以下内部字段：

```text
bucket
object_name
MinIO URL
存储凭据
```

文件详情响应：

```json
{
  "code": 200,
  "data": {
    "file": {
      "id": 1,
      "name": "report.pdf",
      "content_type": "application/pdf",
      "detected_content_type": "application/pdf",
      "size": 1048576,
      "uploader_id": 3,
      "validation_status": "validated",
      "validation_policy_version": "file-upload-v1",
      "validation_error_code": "",
      "validated_at": "2026-07-15 10:00:00",
      "created_at": "2026-07-15 10:00:00"
    },
    "download_url": "/api/admin/files/1/download?expires=...&signature=..."
  }
}
```

只有允许访问时才返回 `download_url`；只有验证通过的 JPEG、PNG、WebP 才返回 `preview_url`。

## 验证状态与访问矩阵

| 状态 | 详情 URL | 下载 | 预览 | 可重新验证 |
|---|---|---|---|---|
| `validated` | 下载；图片额外预览 | 规范 MIME，强制附件 | 仅 JPEG/PNG/WebP | 否 |
| `legacy_unverified` | 仅下载 | `application/octet-stream`，强制附件 | 否 | 是 |
| `validation_error` | 仅下载 | `application/octet-stream`，强制附件 | 否 | 是 |
| `blocked` | 不返回访问 URL | 否 | 否 | 否 |

历史记录上线时只回填为 `legacy_unverified`。数据库迁移和服务启动不会读取、解压、删除或重写历史 MinIO 对象，也不会自动批量扫描。

## 接口

管理员文件接口均需要：

```text
Authorization: Bearer <admin_token>
JWT 认证 + 动态 API 权限
```

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/admin/files` | 上传一个 V1 白名单文件 |
| GET | `/api/admin/files` | 分页查询文件记录 |
| GET | `/api/admin/files/:id` | 查询可信元数据和临时应用访问 URL |
| PUT | `/api/admin/files/:id` | 修改展示名称主体，保留规范扩展名 |
| DELETE | `/api/admin/files/:id` | 删除对象和数据库记录 |
| GET | `/api/admin/files/:id/download` | 校验 JWT、权限、有效期和签名后流式下载 |
| GET | `/api/admin/files/:id/preview` | 校验 JWT、权限、有效期和签名后预览图片 |
| POST | `/api/admin/files/:id/revalidate` | 重新验证单个历史或临时失败文件 |
| GET | `/api/admin/files-browse` | 浏览 `files` bucket 对象元数据 |

### 上传

```http
POST /api/admin/files
Content-Type: multipart/form-data
Authorization: Bearer <admin_token>
```

Apifox Body 选择 `form-data`，只添加一个字段：

| Key | 类型 | 必填 |
|---|---|---|
| `file` | File | 是 |

成功响应中的文件名已经清洗，object key 由服务端生成且不会返回。

### 列表和详情

```http
GET /api/admin/files?page=1&size=10&prefix=
GET /api/admin/files/:id
```

`prefix` 仍按内部对象名前缀筛选，但列表结果不会返回对象名。

前端迁移要求：

- 从详情响应读取 `download_url`，仅在存在时显示下载操作。
- 仅在详情返回 `preview_url` 时显示图片预览。
- 不再根据 `bucket`、`object_name` 或历史 MinIO 地址拼接 URL。
- 临时 URL 仍受 JWT 和动态权限保护；前端应携带 `Authorization` 请求 Blob，再触发下载或展示，不要把它当作匿名公开地址。
- URL 过期、签名被篡改、访问模式不匹配或签名用户与当前用户不同都会被拒绝。

### 改名

```http
PUT /api/admin/files/:id
Content-Type: application/json

{
  "name": "季度报告"
}
```

服务端只接受安全的展示名称主体，并保留原规范扩展名。提交路径、控制字符、危险双扩展名或试图改变扩展名会被拒绝；bucket、object key 和验证状态保持不变。

### 下载与预览

下载和预览 URL 必须先通过详情接口获取，不应由客户端自行构造。

下载响应设置：

```text
Content-Disposition: attachment
X-Content-Type-Options: nosniff
Cache-Control: private, no-store
```

预览只允许 `validated` JPEG、PNG、WebP，并使用内联响应。PDF、Office、TXT、CSV 以及未验证文件均不允许内联预览。

### 重新验证

```http
POST /api/admin/files/:id/revalidate
Authorization: Bearer <admin_token>
```

仅接受 `legacy_unverified` 或 `validation_error`：

- 通过当前策略：更新为 `validated`。
- 确认不支持、损坏或危险：更新为 `blocked`，但 V1 不自动删除原对象。
- 对象存储或网络临时失败：保持对象并更新为 `validation_error`，以后可以重试。
- 对 `validated` 或 `blocked` 重复调用：返回 HTTP 409。

### MinIO 对象浏览

`GET /api/admin/files-browse?prefix=` 只用于管理员查看 `files` bucket 的对象元数据：

- 不自动创建文件记录。
- 不自动赋予验证状态。
- 不提供绕过文件状态策略的下载 URL。
- 浏览到孤立对象不代表该对象已经成为受管文件。

## 稳定错误响应

文件上传相关错误保留数字 `code`，并增加稳定字符串 `error_code`：

```json
{
  "code": 415,
  "error_code": "FILE_TYPE_NOT_ALLOWED",
  "msg": "文件类型不受支持"
}
```

主要 HTTP 分类：

| HTTP | 含义 |
|---:|---|
| 400 | multipart、文件名或请求参数错误 |
| 413 | 请求体、文件或 OOXML 解压资源超限 |
| 415 | 类型不支持或类型不一致 |
| 422 | 编码、图片、PDF 或 Office 内容无效 |
| 404 | 文件记录或对象不存在 |
| 409 | 当前验证状态不允许该操作 |
| 500/503 | 数据库或对象存储错误 |

错误消息不会返回底层 ZIP/XML/图片解析器、数据库或 MinIO 原始错误。

## 文件轮转

文件轮转继续使用：

```yaml
file_rotation:
  enabled: true
  days: 30
  hot_bucket: "files"
  cold_bucket: "files-archive"
  batch_size: 100
```

轮转修改记录内部 bucket，不改变 API DTO。应用下载接口从记录指定的私有 bucket 流式读取，因此文件进入冷 bucket 后仍遵循同一验证状态和访问策略。

## Apifox 验证顺序

1. 重新导入 `http://localhost:8080/docs/openapi.json`。
2. 管理员登录并设置 `admin_token`。
3. 上传合法 JPEG/PNG/WebP、PDF、DOCX/XLSX/PPTX、UTF-8 TXT/CSV，确认状态为 `validated`。
4. 分别上传额外文件 part、空文件、超限文件、危险双扩展名、不支持格式和 MIME 不一致文件，确认返回稳定 `error_code` 且没有文件记录。
5. 查询列表和详情，确认不包含 `bucket`、`object_name` 或 MinIO URL。
6. 使用详情返回的 `download_url` 携带管理员 Token 下载文件，检查附件、`nosniff` 和私有缓存响应头。
7. 对合法图片使用 `preview_url`；对 PDF、Office、文本或未验证文件确认预览返回 409。
8. 修改展示名称，确认规范扩展名不变；尝试改变扩展名并确认被拒绝。
9. 准备 `legacy_unverified` 或 `validation_error` 记录，验证重新验证成功、封锁和临时失败状态转换。
10. 浏览 MinIO 对象，确认孤立对象不会自动成为文件记录。
11. 删除测试文件并确认记录和对象均已删除。
